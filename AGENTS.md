# Работа над QA Portal: кто за что отвечает

Над сайтом работают два помощника в одной папке и одной ветке. Чтобы не затирать друг друга, у каждого свои файлы.

## Codex — дизайн
- Внешний вид: `css/*`, `js/theme.js`, `img/portal-circuits.svg`, оформление страниц магазина и лаборатории.
- Иллюстрации и схемы: `img/methods/*`, `js/kb-visuals.js` (подписи к схемам согласует с текстом темы).
- Разметка и вывод страниц: `js/learn.js`, `js/kb.js`, `js/portal*.js` — **меняй вид, но не меняй поля данных**, которые они выводят (`explanation`, `examples`, `exampleLabels`, `tasks`, `template`, `templateAfter`, `image`, `short`, `more`, `good`, `bad`, `mistakes`, `steps`). Если для дизайна нужно новое поле, добавь его как необязательное.

## Claude — содержание
- Тексты пар: `js/learn/guided/k1-N.js`.
- Тексты базы знаний: `js/study-content.js`. **Не правь его вручную**: он собирается генератором из материалов ментора вне этого репозитория. Ручные правки пропадут при следующей сборке.
- Картинки внутри уроков: `img/lesson-*.svg`.
- Требования кофейни (`js/shop-requirements.js`) и учебные баги магазина — не трогать без запроса преподавателя.

## Общие правила
- Перед коммитом запусти тесты: `node --test tests/<файл>.cjs` для каждого файла в `tests/` (запуск всей папки на Windows не работает).
- При изменении JS или CSS поднимай `?v=` у этого файла в HTML.
- Не раскрывай и не исправляй учебные баги магазина в уроках, базе знаний и коде.
- Коммить своё отдельными коммитами с понятным описанием. **Не пушь** и не сливай в `main` без команды преподавателя: `main` сразу публикуется на GitHub Pages.
- Если нужно изменить чужой файл — опиши, что и зачем, в сообщении коммита, а крупное согласуй с преподавателем.
