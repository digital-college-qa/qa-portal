# Сервер учебных тестов QA Portal

Docker запускает приложение в контейнере. SSH нужен только администратору для управления VPS. Студенты входят в окно «Автотесты» через HTTPS по логину и паролю; SSH и Docker им не доступны.

## Запуск с ноутбука через Discord

Основной режим для текущего класса: [инструкция LAPTOP.md](LAPTOP.md). Кнопки находятся в существующей панели «Журнал» бота. На ноутбуке работает агент, сервер и временный Cloudflare Tunnel включаются только на урок. В этом Windows-режиме Docker не требуется.

## Что работает

Сервис запускает настоящий Chromium через Playwright. Принимается небольшой учебный поднабор JavaScript: `test`, `expect`, `const`, `await`, поддержанные методы `page`, локаторов и `request`. Код разбирается Acorn и исполняется интерпретатором разрешённых команд. `eval`, системные команды, импорт модулей, доступ к файлам, циклы, функции пользователя, `page.evaluate` и произвольные адреса недоступны. Все действия и проверки вызывают реальный Playwright.

После каждого оператора возвращаются статус, время, снимок браузера и изменения учебной корзины/цен. На сайте отображается ход выполнения; после теста результат переносится в кофейню браузера студента. Тесты получают копию текущей учебной сессии, без паролей и аккаунтов магазина. Между отдельными тестами создаются чистые браузерные контексты с одинаковыми исходными данными.

## Развёртывание после получения сервера и домена

Нужен Linux VPS с Docker Compose, примерно 2 vCPU / 4 GB RAM, домен с DNS-записью на VPS и доступ администратора. Сейчас конфигурация подготовлена, но сервер не приобретён и не развёрнут.

Из каталога `server`:

1. Скопировать `.env.example` в `.env`, указать домен.
2. Создать каталог `secrets`: на Linux `sudo install -d -m 700 -o 1000 -g 1000 secrets`. Пользователь контейнера — UID 1000. Каталог исключён из Git.
3. `docker compose build runner accounts`, затем `docker compose run --rm accounts init`.
4. `docker compose run --rm accounts add student01`: сгенерированный пароль передать только этому ученику. Повторить для остальных. Хранятся соль и scrypt-хеш; открытой регистрации нет.
5. `docker compose config`, затем `docker compose up -d runner gateway`. Проверить `https://<домен>/health`.
6. В лаборатории версии 2.0 ввести адрес, выданный логин и пароль. Пароль не сохраняется, токен живёт в памяти вкладки до 6 часов.
7. Проверить успешный и падающий тест, отмену, неверный пароль и разделение сессий. Docker на этом ноутбуке отсутствует: сборку и Chromium sandbox нужно проверить на целевом Linux VPS.

Управление аккаунтами: `docker compose run --rm accounts list`, `... reset student01`, `... disable student01`. Смена пароля и отключение отзывают действующие токены при следующем запросе и останавливают активный запуск. Файл аккаунтов читается заново; перезапуск сервера не нужен.

Для доступа с другого домена изменить `ALLOWED_ORIGINS` на точные разрешённые origins. `*` не использовать. Стандартный адрес портала уже указан. API браузерного стенда и сервер Playwright различаются: локальный API доступен без сервера, а реальные тесты требуют этого сервиса.

## Ограничения и защита

- Пароль проверяется через scrypt и constant-time сравнение. Нет пароля по умолчанию, публичной регистрации или загрузки файлов.
- Восемь неудачных попыток входа в минуту на адрес, не более пяти запусков в минуту на сессию, максимум два одновременных запуска.
- Один запуск: до трёх тестов, 35 операторов на тест, 8000 символов, 45 секунд. Сервер ограничивает размер запросов, количество сессий и срок хранения результатов.
- Задания исполняются отдельными процессами с лимитом памяти Node. На Linux остановка убивает всю группу процессов, включая браузер. После завершения сессии/таймаута задания отменяются.
- Контейнер непривилегированный, без Linux capabilities, без Docker socket, с read-only filesystem и ограничениями CPU/RAM/PID. Chromium sandbox включён. Официальный профиль seccomp взят из Playwright v1.62.1; SHA256: `cc3e61cabda6bbc1e53e54d27ba4d55a9d3be829b6dd1a596f4a7b31b1cc7849`.
- Runner находится во внутренней сети Docker, не имеет опубликованного порта и выхода в Интернет. Снаружи доступны только 80/443 gateway. Рабочий API и `/shop/` закрыты в gateway, а браузер допускает только локальные учебные ресурсы.
- На VPS обновлять ОС и Docker, закрыть прочие входящие порты; SSH оставить администратору по ключу. Ограничения приложения не заменяют настройку и обновление сервера. Полной гарантии от компрометации один контейнер или пароль не даёт.

## Поддержанный код

```js
import { test, expect } from '@playwright/test';

test('Капучино в корзине', async ({ page, request }) => {
  await request.delete('cart');
  await page.goto('product.html?id=3');
  await page.getByRole('button', { name: 'M', exact: true }).click();
  await page.getByRole('button', { name: /В корзину|Себетке/ }).click();
  await page.goto('cart.html');
  await expect(page.getByText('Капучино', { exact: true })).toBeVisible();
});
```

Учебный API fixture использует пути `products`, `products/3`, `cart` и `cart/items`, без полного URL. Его изменения синхронизируются с браузером теста. Объект `page` работает только с разрешёнными страницами магазина. Произвольные URL, общие библиотеки JavaScript и пользовательские функции сознательно не поддержаны.

Проверки кода: `npm test`. Проверка полного запуска без Docker: `npm run test:integration` (требуются установленные Chromium и Playwright). Docker-сборка на этой Windows-машине не проверена: Docker отсутствует; конфигурацию требуется проверить на целевом Linux VPS.

Официальные источники: [Playwright Docker](https://playwright.dev/docs/docker), [безопасность Docker Engine](https://docs.docker.com/engine/security/), [ограничения ресурсов](https://docs.docker.com/engine/containers/resource_constraints/).
