# Встроенные учебные инструменты

Статус: подготовлены интерфейс и точки подключения. API-сервис и runner пока не подключены. `labs.html` позволяет составлять запросы, валидировать JSON и редактировать тест. Он не показывает придуманные ответы или результаты тестов.

## Версии

`js/labs/runtime.js` содержит матрицу инструментов: 1.0 без лаборатории, 1.5 с API-клиентом, 2.0 с API-клиентом и Playwright. Это версия учебного инструмента, а не утверждение о готовности новой версии магазина. Возможности лаборатории считаются отдельно от прироста функций кофейни на 20%.

## API

Точка подключения: `QATraining.attach('api', { execute({ version, payload, signal }) { ... } })`.

`payload`: `{ method, path, headers, body? }`. `path` относителен выделенному API-префиксу; адаптер не должен разрешать выход в произвольные ресурсы сайта. Тело - JSON-строка, если задано. Токен не сохраняется и скрывается в предпросмотре. Прямое сохранение секретов в localStorage не допускается.

Адаптер возвращает реальные `{ status, durationMs, headers, body, requestId, traceId }`. Ошибочный HTTP-статус должен остаться виден студенту; 4xx/5xx не заменяются фиктивным успешным ответом. Поддерживаются отмена, таймаут, CORS и разделение учебных сессий.

Планируемый учебный контракт (ещё не активен): `GET /products`, `GET /products/:id`, `POST /auth/login`, `GET /cart`, `POST /cart/items`, `PATCH /cart/items/:id`, `DELETE /cart/items/:id`, `POST /orders`. Для каждой версии контракт должен задать точные тела, коды, границы и ошибки. Примеры в базе знаний помечены как учебный проект контракта.

## Playwright

Точка подключения: `QATraining.attach('playwright', { execute({ version, payload, signal }) { ... } })`. В `payload.code` передаётся JavaScript-тест с `@playwright/test`.

Настоящий Playwright запускается отдельным Node.js runner с браузером, не через `eval` в странице. Перед подключением необходима отдельная изолированная среда на запуск, квоты, таймаут, разрешённая цель тестирования и очистка среды. Нельзя исполнять загруженный код в процессе основного сервиса или открывать произвольное выполнение команд на машине ментора.

Ответ: `{ runId, status, tests: [{ title, status, durationMs, error? }], artifacts: [] }`. Остановка по AbortSignal должна отменять задание на runner, а не только скрывать ожидание в клиенте. Предусмотреть stdout/stderr, снимок падения и trace. Артефакты доступны только в соответствующей учебной сессии.

Для начала обучения: `page.goto`, `getByRole`, `getByTestId`, `click`, `fill`, `expect(...).toBeVisible/toHaveText/toHaveCount` и простые API-проверки через fixture `request`. Настройки runner задают `baseURL` выбранного стенда; тесты не зависят от порядка запуска.

## Согласование с магазином

При реализации стендов 1.5/2.0 подключить эти инструменты к переключению версии, контракту, данным и traceId журнала. Применить общие условия и тестовые данные в UI и API. Не публиковать реестр багов и ответы ментора в клиентских ресурсах. Сейчас файлы ключей находятся вне каталога Git-репозитория.
