# Лаборатория поверх кофейни

`labs.html` показывает кофейню в iframe и независимые немодальные окна API, автотестов, документации и журнала. Окна перемещаются через Pointer Events, масштабируются штатным resize, сворачиваются в dock. Положение сохраняется; Escape сворачивает активное окно. На узких экранах окно занимает доступную ширину.

## Рабочий локальный API

`api-worker.js` перехватывает только пути `training-api/*` в scope сайта. Статические ресурсы и навигация не кешируются и не подменяются. Через MessageChannel запрос направляется магазину состояния в активной лаборатории. Получается наблюдаемый fetch/Response с HTTP-статусом, JSON и X-Request-Id. Это учебная API-среда в браузере, не удалённый backend кофейни.

`js/labs/store.js` проверяет запросы и работает с теми же `qc_cart`, `qc_orders` и `qc_product_overrides`, что использует сайт. `js/labs/shop-bridge.js` применяет изменения к каталогу; родитель уведомляет iframe, а `QAShop.refresh()` перерисовывает страницу. Данные не передаются другим студентам. Перезагрузка не теряет цены и корзину. `POST /session/reset` сбрасывает только изменения каталога и корзину.

Контракт: `GET /products`, `GET/PATCH /products/:id`, `GET/DELETE /cart`, `POST /cart/items`, `PATCH/DELETE /cart/items/:id`, `GET /orders`, `POST /session/reset`. Полная инструкция с кодами и ограничениями находится в базе знаний `#api-client`.

## Настоящие автотесты

Сервер в `server/` использует Playwright и Chromium. Это ограниченный учебный язык: разрешённые операции JavaScript разбираются Acorn и диспетчеризуются на реальные Playwright методы. Произвольный JavaScript не исполняется; пользовательский код не передаётся в eval/Function/vm или оболочку. Из браузера разрешён только учебный сайт сервера; API fixture обращается только к API своего запуска.

Frontend: вход `POST /auth/login`, запуск `POST /runs`, получение прогресса `GET /runs/:id`, остановка `DELETE /runs/:id`, выход `POST /auth/logout`. Bearer-токен хранится в памяти, пароль после входа очищается. URL сервера сохраняется отдельно. CORS разрешает только настроенные origins.

Каждый запуск получает ограниченную копию текущей корзины, цен, языка и версии. После оператора возвращаются статус, длительность, снимок реального браузера и состояние. На фоне лаборатории показывается браузер Playwright, а состояние корзины/цен синхронизируется с локальным магазином. После завершения магазин открывает последнюю страницу теста. В новой testcase создаётся новый браузерный контекст с исходной копией состояния.

Docker Compose, TLS gateway, пароль через Docker secret, ограничения процессов/ресурсов и инструкция администратора находятся в `server/README.md`. Серверная часть проверена локально на Windows с настоящим Chromium, включая успешный/падающий тест, изменение корзины, отмену, ограничения синтаксиса и изоляцию сессий. Docker и Chromium sandbox на целевом Linux VPS ещё должны быть проверены: Docker на текущей машине отсутствует. Общедоступного сервера пока нет, поэтому публичная кнопка запуска становится активной только после входа на развёрнутый сервер.
